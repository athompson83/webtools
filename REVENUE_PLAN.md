# Revenue Plan — SEO-to-revenue proof

## Objective
Make GroundExact prove organic discovery and monetization before adding more properties.

## Governing rule
Revenue-path work has priority over feature expansion. Inspect current repository/provider state first and reuse what exists. Do not duplicate infrastructure. Run the smallest relevant local tests first; use hosted CI only when it adds evidence.

## MVP — prove the transaction
- [ ] Keyword/SERP validation for existing calculators
- [ ] prioritize high-intent pages
- [ ] technical SEO/schema/internal linking/AEO
- [ ] Search Console/analytics
- [ ] affiliate/ad/lead monetization matched to intent
- [ ] conversion events
- [ ] publish only reviewed useful tools
- [ ] evaluate revenue per landing page before new site.

## Beta — prove repeatability
- [ ] Admit a bounded non-owner cohort only after MVP evidence passes.
- [ ] Measure activation, conversion, failures, support burden, variable cost and retention/reuse signal.
- [ ] Fix observed blockers and defer unrelated features.

## Production — scale after proof
- [ ] Establish monitoring, monetization/billing reconciliation, support and appropriate recovery.
- [ ] Expand SEO/AEO/acquisition only around validated demand and truthful capabilities.

## Revenue success criterion
**Organic non-owner traffic reaches a useful calculator and produces a measurable monetization event; economics are recorded by landing page.**

## Stop / adjust criteria
- No new major feature family before the success criterion.
- No new database/project/service when an existing governed resource suffices.
- No redundant CI spend.
- Change the offer before architecture when market evidence contradicts the offer.

## Evidence
Record exact commit/deployment, customer class (no PII/secrets), acquisition source, transaction/monetization event, outcome, variable cost, failures and next constraint in existing project-control artifacts.
